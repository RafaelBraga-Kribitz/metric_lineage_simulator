# Power BI build kit — DTC driver tree

This folder turns the studio's DTC model into a Power BI report you can build by hand in
about 30 minutes. A `.pbix` file cannot be generated here; building it is an owner step.
Everything except this README is generated by `cd driver_tree_studio && npm run export` and
checked by tests. Do not edit the generated files by hand.

| File | What it is |
|---|---|
| `kpi_definitions.csv` | KPI dictionary (Kennzahlen-Steckbrief): id, EN/DE name, definition, unit, layer, identity formula, declared assumptions, owner, source table, grain, refresh, dimensions |
| `kpi_tree.sql` | `kpi_definitions` table + `kpi_inputs` table + `kpi_tree` view that recomputes every identity metric per period (ANSI SQL; runs on SQLite, DuckDB, PostgreSQL) |
| `measures.dax` | One DAX measure per metric. Identities only; modeled/hypothesized edges are documented, never computed |
| `kpi_inputs_SYNTHETIC.csv` | **SYNTHETIC** inputs: 12 months, each input = seed baseline × (1 + N(0, 5%)), seed 11. Not data about any business |
| `theme.json` | Report theme parsed from the studio's CSS design tokens (`app/globals.css`) |

German labels (Deckungsbeitrag, Warenkorbwert, Konversionsrate, …) are ILLUSTRATIVE textbook
terms for display, not any company's internal definitions.

## Build steps

1. **Get data → Text/CSV** → `kpi_inputs_SYNTHETIC.csv`. Name the table `kpi_inputs`. Types:
   `period` = Date, `metric_id` = Text, `value` = Decimal number.
2. **Get data → Text/CSV** → `kpi_definitions.csv`. Name it `kpi_definitions`. Leave it
   unrelated (it is a data dictionary page, not a dimension).
3. **Model view → New table** (optional): `Calendar = DISTINCT(SELECTCOLUMNS(kpi_inputs, "period", kpi_inputs[period]))`,
   relate `Calendar[period]` 1:* `kpi_inputs[period]`.
4. **Modeling → New measure**, once per block in `measures.dax` (copy the line after each
   comment). Order matters only for readability; DAX resolves references.
5. **View → Themes → Browse for themes** → `theme.json`.
6. Build the three pages below.

## Page spec

**Page 1 · Driver tree (Werttreiberbaum)**
- Card: `Contribution Profit`. Cards: `Net Revenue`, `Variable Costs`, `Orders`.
- Arrange cards in the studio's tree layout (north star on top, then outcomes, drivers,
  inputs; the `layer` column of `kpi_definitions` says which row each metric belongs to).
  Power BI's decomposition-tree visual splits by dimensions, not by formulas, so it is not
  a substitute for an identity tree.
- Line chart: `Contribution Profit` by `period`.

**Page 2 · Funnel (Konversionstrichter)**
- Funnel or clustered bar: `Product View Rate`, `Add to Cart Rate`, `Checkout Start Rate`,
  `Purchase Completion Rate` (one period selected via slicer), plus card `Conversion Rate`.

**Page 3 · KPI dictionary (Kennzahlen-Steckbrief)**
- Table of `kpi_definitions`: `name`, `name_de`, `definition`, `formula`, `assumptions`,
  `owner`, `warehouse_table`, `calculation_grain`, `update_frequency`.
- Text box with the studio's caveat: modeled and hypothesized relationships are assumptions,
  not measured effects.
